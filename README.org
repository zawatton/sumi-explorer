#+TITLE: Sumi Explorer

* Standalone desktop file explorer

Sumi Explorer is a NeLisp AOT GTK4/GIO application with an optional GNU Emacs
client. GNU Emacs builds it; the resulting desktop executable runs independently.
See the [[file:docs/file-explorer.md][application]], [[file:docs/file-operations.md][operation]], and [[file:docs/file-batches.md][batch contracts]].

The GUI supports navigation, Ctrl/Shift multiple selection, associated-application
opening, a portable context menu, application Properties, and
asynchronous copy, move, rename, new-directory, GIO Trash and ZIP operations,
plus session Undo. Application Properties is a portable application dialog.
On Windows, =Native Shell Menu= invokes system handlers and =Permissions= invokes
the native Security editor. Their validation boundaries are recorded below.

Single-row Copy/Move takes an exact new destination path. Multiple-row Copy/Move
takes an existing destination directory and preflights the complete batch.
Trash confirms frozen targets; Cancel is cooperative. Existing targets are
never overwritten or merged. Failure/cancellation can leave a reported partial
new destination; completed batch items remain and untouched items are skipped.
Move has no copy/delete fallback, so cross-filesystem moves can fail safely.

Incoming DND accepts multiple local file/directory/symlink COPY drops through
the shared bounded engine. Incoming MOVE and remote paths are rejected.
GTK drop acceptance means queued, not a completed filesystem copy; the GUI
reports actual completion and partial output. Owned paths/context remain alive
through completion. The sender receives no asynchronous filesystem result.
Outbound DND exports every selected path; the receiver owns its operation.

* Build and run

Install GTK4 and libarchive development libraries with =pkg-config= metadata,
a C compiler/linker driver (=cc= by default), GNU Emacs, and Git. The public NeLisp AOT compiler is
an external build-time dependency. =explorer/build.el= and the Linux
=tools/check.sh= helper download nothing. The Windows validation driver's
explicit =-PrepareEmacs= step downloads and checksum-verifies portable GNU Emacs.

#+begin_src sh
  git clone https://github.com/zawatton/sumi-explorer.git
  cd sumi-explorer
  mkdir -p target/deps
  git clone https://github.com/zawatton/nelisp.git target/deps/nelisp
  git -C target/deps/nelisp checkout f3551799d210ed32f594383997843f0e1bf25e24
  export NELISP_REPO_ROOT="$PWD/target/deps/nelisp"
  (ulimit -v 8388608; emacs -Q --batch -l explorer/build.el)
  ./target/sumi-explorer
#+end_src

That compiler revision was used for recorded Linux validation. Set
=NELISP_REPO_ROOT= for another existing checkout; the builder otherwise looks
for sibling =../nelisp=. Set =CC= to select another compiler driver. The shell
memory cap is 8 GiB. Compiler sources and build outputs under =target/= are ignored.
Both =pkg-config --cflags gtk4 libarchive= and =pkg-config --libs gtk4 libarchive=
must resolve. The build compiles the small OS adapter alongside the NeLisp
object; Windows linking additionally uses the system Shell/COM libraries.

The app defaults to the user's home directory and creates a private temporary
session. =SUMI_EXPLORER_ROOT= chooses its initial directory. A client can supply
=SUMI_EXPLORER_SESSION=; the app never removes a supplied session.

The build selects native x86_64/aarch64 ELF, COFF, or Mach-O. Windows output is
=target/sumi-explorer.exe=. Linux has executable GUI evidence. Windows x86_64
COFF and Apple Silicon Mach-O object emission were checked. Native Windows builds,
dedicated bridge suites and four Emacs/application workflows passed on the
=windows-2022= runner; see the source-bound Windows evidence. Native ACL
Apply/Cancel, full Windows interaction/packaging and macOS application runtime remain
unverified. Intel Mac object emission currently fails on an unsupported =plt32=
relocation in the compiler. Object emission is not runtime support. See GTK's
setup documentation for [[https://www.gtk.org/docs/installations/windows/][Windows]] and [[https://www.gtk.org/docs/installations/macos/][macOS]].

The [[file:docs/windows-validation.md][Windows validation procedure]] separates the automated CI evidence
from the remaining manual application, native Shell and ACL checks.

* Emacs commands

From this repository, or through your existing =load-path= configuration:

#+begin_src emacs-lisp
  (add-to-list 'load-path (expand-file-name "explorer" default-directory))
  (require 'sumi-explorer)
  (sumi-explorer-start default-directory)
  (sumi-explorer-open-directory default-directory)
  (sumi-explorer-selected-files)
  (sumi-explorer-properties)
  (sumi-explorer-refresh)
  (sumi-explorer-stop)
#+end_src

Use =M-x sumi-explorer-copy=, =sumi-explorer-move=, =sumi-explorer-rename=,
=sumi-explorer-mkdir=, or =sumi-explorer-trash=. Sources default to the GUI
selection or prompt for a source. Copy/Move prompts for an exact new path;
Rename stays in its parent. Interactive Trash confirms the exact target.

For multiple rows use =M-x sumi-explorer-copy-files=, =sumi-explorer-move-files=,
or =sumi-explorer-trash-files=. Copy/Move prompts for an existing directory;
Trash confirms the complete frozen list. =sumi-explorer-select-files= sets
selection from Lisp; =sumi-explorer-selected-files= returns its display order.

#+begin_src emacs-lisp
  (sumi-explorer-begin-operation "copy" source-path exact-new-destination)
  ;; Optional cooperative cancellation; await still reports the actual result.
  (sumi-explorer-cancel)
  (sumi-explorer-await 30)

  (let ((id (sumi-explorer-begin-batch "copy" selected-paths existing-directory)))
    (sumi-explorer-await 30)
    (sumi-explorer-batch-result id))
#+end_src

Timeout/C-g retains the same pending request without retrying it. Resume with
=M-x sumi-explorer-await=. After a batch error use =sumi-explorer-batch-result=
with its retained ID to inspect =ok=, =error=, and =skipped= items. Malformed or
oversized manifests may have no new result. GUI actions cannot replace a protocol
batch result. Selection/batches are bounded to 256 paths and 1 MiB encoded data;
Unicode, line breaks, semicolons, and backslashes remain data, never delimiters.
Oversized results are rejected before mutation.

The client exchanges UTF-8 files in a private session, never evaluates received
Lisp, and never builds shell commands from names. Durable =response.ini= is
separate from live GUI state. Normal stop requests quit and retains the session
while an operation finishes. Prefix/explicit forced stop can interrupt a copy.

* ZIP, session Undo and native platform operations

The [[file:docs/advanced-features.md][advanced contract]] describes this increment. The native engine, client commands
and GUI actions are implemented, with Linux regression evidence recorded below.
The Windows validation procedure records native execution separately.

#+begin_src emacs-lisp
  (sumi-explorer-zip-create exact-new-archive selected-paths 30)
  (sumi-explorer-zip-extract archive-path exact-new-directory 30)
  (sumi-explorer-undo-history)
  (sumi-explorer-undo nil 30) ; Newest group from one snapshot; no stale retry.
  (sumi-explorer-permissions target-path)
  (sumi-explorer-set-permissions target-path "0640" 10) ; POSIX only.
  (sumi-explorer-shell-menu selected-paths) ; Windows only.
#+end_src

The mutation/editor functions are also =M-x= commands. Interactive ZIP creation
freezes the selected input vector before prompting for the exact unused ZIP
path. Extraction prompts for one archive and an exact unused directory. ZIP
inputs use the same 256-path/1-MiB manifest bound; extraction rejects unsafe
names, links, special entries and unsupported content before output. It does
not overwrite or merge. Only bounded single-disk classic ZIP store/deflate is
supported, with at most 65535 entries; ZIP64 is unsupported. See the contract for
streamed size/depth/name limits.
Timeout/C-g retains the same pending request; resume with =sumi-explorer-await=.

Undo is limited to 32 groups in the current session and is not a persistent
backup. =sumi-explorer-undo-history= returns newest-first group alists under
=groups=; an explicit group ID must still be the newest valid group. The host
revalidates identities/fingerprints and refuses changed objects, existing
restore targets and stale IDs. Supported app-managed outcomes include copy,
move, rename, new directory, ZIP outputs and POSIX mode changes. Trash Undo
requires a unique verified backend handle to the actual trashed object and a
no-copy-fallback restore; ordinary GIO Trash success alone does not promise
Undo. Unsupported backends report recovery unavailable. Partial reversal keeps
unresolved entries. External writers can still race these checks.
Older groups are rebased only for proven exact-root transitions and bounded
parent-witness relationships. Other ancestor relationships and shared-batch
dependencies are conservatively refused rather than treated as arbitrary safe
Undo chains. On Windows the native identity/metadata stamp supports local NTFS
only. Missing stamp/provider capability preserves a real mutation's success and
reports =Undo unavailable=; it never creates a recovery promise from incomplete
identity evidence.

=sumi-explorer-permissions= opens a single-target portable mode prompt on POSIX
or the native Windows Security property page. Its acknowledgement means editor
invocation, not ACL Apply, editor closure or even proof that Security was shown.
=sumi-explorer-set-permissions= applies an explicit three/four-digit mode in
=0000..0777= on POSIX and rejects Windows. Symlink targets are rejected.
=sumi-explorer-shell-menu= freezes explicit targets, or selection/current
directory, and invokes Windows Shell handlers; other platforms return an error.
External Shell verbs and native ACL edits are not app-managed Undo outcomes.
The GUI exposes =Create ZIP=, =Extract ZIP=, =Undo=, =Permissions= and
=Native Shell Menu=. Prompts retain frozen targets. Native Windows handler
coverage and ACL Apply/Cancel require their own Windows acceptance. Ctrl+Z
activates app Undo outside text-editing widgets.

** Tabs, navigation and presentation

Up to 64 tabs have stable IDs, independent selection and up to 128 history
entries. New tabs become active; closing the last tab is rejected. A new window
has its own process/session and can outlive the original window. Its command
acknowledgement confirms process spawning, not GUI readiness.

#+begin_src emacs-lisp
  (sumi-explorer-new-tab)                 ; Current GUI directory.
  (sumi-explorer-new-tab another-directory)
  (sumi-explorer-tabs)                    ; Independent workspace snapshot.
  (sumi-explorer-activate-tab tab-id)
  (sumi-explorer-back)
  (sumi-explorer-forward)
  (sumi-explorer-home)
  (sumi-explorer-close-tab)
  (sumi-explorer-new-window another-directory)

  (sumi-explorer-filter "literal filename text")
  (sumi-explorer-sort "size")             ; name, size, date, type.
  (sumi-explorer-order "desc")            ; asc or desc.
  (sumi-explorer-show-hidden t)            ; nil hides hidden files.
  (sumi-explorer-set-view "details")       ; list or details.
  (sumi-explorer-view-settings)
#+end_src

Filters are case-folded literal filename matches in the current directory,
limited to 256 Unicode scalar characters. They are not recursive search or
indexing. Sorting keeps directories first and preserves selected identities;
filtering/hiding removes newly invisible selections. Settings belong to each
tab. Workspace/view snapshots are independently consistent last publications,
not durable command results or freshness guarantees after an I/O failure.

** Clipboard, context actions and bookmarks

Clipboard commands freeze the visible GUI selection. Paste uses the shared
no-overwrite engine and acknowledges only actual completion; timeout/C-g leaves
the same request available to =sumi-explorer-await=.

#+begin_src emacs-lisp
  (sumi-explorer-clipboard-copy)
  (sumi-explorer-paste destination-directory) ; nil uses active directory.
  (sumi-explorer-clipboard-cut)
  (sumi-explorer-paste)

  (sumi-explorer-bookmark-add)                ; Active directory.
  (sumi-explorer-bookmark-add another-directory)
  (sumi-explorer-bookmarks)
  (sumi-explorer-bookmark-open another-directory)
  (sumi-explorer-bookmark-remove another-directory)
#+end_src

External clipboard file lists support COPY only. Cut is authorized only while
this host still owns its internal clipboard provider/generation; external or
cross-process Cut compatibility is not promised. Completed Cut entries are
removed only from that unchanged generation; failed/skipped entries remain.
An unresponsive external clipboard owner can delay GTK/X11's cancellation
callback. The request stays pending and its context stays alive until that
callback; there is no fixed external clipboard cancellation deadline.

Bookmarks store up to 64 unique absolute local directories in the platform's
user-config =sumi-explorer/bookmarks.ini=. Independent windows lock, reload and
atomically replace it. A competing/stale exclusive lock or corrupt config
returns an explicit error without silently stealing the lock or replacing data.

Context actions expose open/new tab/new window, copy/cut/paste, rename,
new folder, Trash and Properties. Rename stays single-target; prompts and Trash
confirmation retain frozen targets. Workspace shortcuts are Ctrl+T/N/W,
Ctrl+Tab/Ctrl+Shift+Tab, Alt+Left/Right/Up, Ctrl+L and F5. File-view actions use
Ctrl+C/X/V/A, F2, Delete and Ctrl+Shift+N. Editable controls retain normal text
shortcuts. These workflows do not add permanent deletion, archives, ACL editing,
indexing or undo.

* Linux validation

Client tests need GNU Emacs, Python 3 for a startup fixture, and standard =cat=
and =true= utilities. Native tests additionally need the built binary, Xvfb
(=xvfb-run=), xdotool, xwininfo, ImageMagick's =import=, xclip, Nautilus,
=dbus-run-session=, =pkg-config= metadata for GTK4/libarchive and the
=CC= compiler driver (default =cc=). They also need the external NeLisp AOT
compiler for a focused acceptance unit, even after the app has been built.
Keep the pinned =NELISP_REPO_ROOT= export above for later test commands. The
helper respects an explicit checkout path (relative paths resolve against this
repository), otherwise tries =target/deps/nelisp= and then sibling =../nelisp=;
it requires =nelisp-aot-compiler.el= under =lisp/= or =src/= and downloads nothing.
Python implements tests and record verification, not the application.
Fixtures, configuration and Trash data are isolated by the helper.

The helper works from any current directory, downloads nothing, caps its children
at 8 GiB, and fails on missing dependencies. =client= runs warning-as-error byte
compilation and client ERT without GTK/a binary. =native= runs all native suites;
=all= runs both. Optional =SUMI_EXPLORER_TEST_BIN= selects another built executable.
Before starting any native suite, the helper replaces inherited =XDG_CONFIG_HOME=
with a private temporary config directory so old and new tests cannot read or
edit personal bookmarks. Both client and native temporary directories are
removed on exit or interruption; this does not change global settings.

#+begin_src sh
  sh tools/check.sh client
  sh tools/check.sh all
#+end_src

For individual native suites, isolate configuration first, as the helper does.
Python suites accept =--artifacts=; keep diagnostics under ignored =target/=.

#+begin_src sh
  test_config=$(mktemp -d)
  export XDG_CONFIG_HOME="$test_config"
  trap 'rm -r -- "$test_config"' EXIT
  (ulimit -v 8388608; xvfb-run -a python3 tests/explorer-gui-test.py --binary target/sumi-explorer --group all)
  (ulimit -v 8388608; xvfb-run -a dbus-run-session -- python3 tests/explorer-dnd-test.py --binary target/sumi-explorer)
  (ulimit -v 8388608; xvfb-run -a emacs -Q --batch -L explorer -l tests/sumi-explorer-integration-test.el)
  (ulimit -v 8388608; xvfb-run -a python3 tests/explorer-operations-test.py --binary target/sumi-explorer)
  (ulimit -v 8388608; xvfb-run -a dbus-run-session -- python3 tests/explorer-batches-test.py --binary target/sumi-explorer)
  (ulimit -v 8388608; xvfb-run -a dbus-run-session -- python3 tests/explorer-workspace-test.py --binary target/sumi-explorer)
  (ulimit -v 8388608; xvfb-run -a dbus-run-session -- python3 tests/explorer-everyday-test.py --binary target/sumi-explorer)
  (ulimit -v 8388608; xvfb-run -a dbus-run-session -- python3 tests/explorer-advanced-test.py --binary target/sumi-explorer)

The recorded counts are 65 client ERT cases, seven real Emacs/native workflows,
15 batch checks, 12 operation checks, seven DND checks, 12 workspace checks and
21 everyday checks, plus 54 advanced groups, six platform checks, four explicit
non-Windows metadata checks, eleven ZIP unsupported-stub checks and
warning-as-error compilation of four Elisp files.
The GUI suite also
covers protocol, rejection controls, and widget activation. These identify
recorded suites; they do not claim a fresh machine has passed them.
Everyday checks include actual Nautilus clipboard COPY, external multi-directory
DND, delayed clipboard-read cancellation/close and popup invalidation. Its
partial-Cut completion check is an AOT unit using the actual helpers and real
GDK providers with constructed outcomes; it is not a real partial filesystem
failure scenario. Earlier binaries fail the new clipboard/geometry controls.

** Historical validation record

=docs/validation.json= records verified executions' compiler revision, Linux
platform, binary hash, input hashes, suite outcomes, and limitations.
=python3 tools/verify-validation.py= checks its schema and current application,
build, test, and helper hashes. It works without a binary or compiler checkout.
Use repeated =--check client= / =--check emacs_native= options for named criteria.

This validates a historical record's source binding, not current test execution.
Editable JSON cannot independently prove past execution. Optional log hashes
identify original diagnostics without publishing private logs; the verifier
checks their format, not their contents or availability. Run the build/tests
above for new execution evidence. The [[file:tools/ai/file-explorer-progress.org][20-criterion ledger]] maps criteria to
named historical checks; Windows/macOS end-to-end criteria stay pending.

=docs/windows-validation.json= separately records the accepted Windows run,
native binary, actual LF source bytes and suite/log hashes.
=python3 tools/verify-windows-validation.py= checks that historical source binding.
The source set includes =.gitattributes= and the workflow; the native driver
rejects CR bytes before hashing. It does not normalize the tested sources.

=docs/clean-validation.json= records a fresh anonymous public clone of main
=b9ea315cb5e743177d7fdf7533b07db06b7b918f=, a separately fetched public compiler
at the pinned revision, a clean build and the complete helper: 220 defined Linux
checks passed. GTK/system tools and the isolated libarchive SDK remain build
dependencies. Check this receipt with
=python3 tools/verify-validation.py --record docs/clean-validation.json=.

The historical-record verifier requires Python 3.9 or newer.
